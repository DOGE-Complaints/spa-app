## Зачем простыми словами

По ходу аудитов и фич-стори всплывают **мелкие безопасные хвосты**: мёртвый код, неиспользуемые словари/экспорты, дубли констант, оставшиеся после доделок. Каждый из них по отдельности заводить как стори — дорого и шумно. Поэтому здесь — **один накопитель**: складываем такие пункты в реестр ниже по мере обнаружения, а когда наберётся пачка — проходим **одним процессом** (один PR/один wave), прогоняем тесты и закрываем все разом.

Это **первая** такая стори. Первый пункт реестра — мёртвый словарь `languages.*` (HK-001).

## Как это работает (процесс)

1. **Intake.** Нашли мелкий хвост → добавили строку в §«Реестр пунктов» с полным контекстом (path:line, доказательство «не используется», источник находки, риск, как закрыть). Код **не трогаем** в момент интейка.
2. **Накопление.** Пункты копятся. Порог запуска уборки — на усмотрение оператора (ориентир: ≥3–5 пунктов **или** перед релизом).
3. **Batch sweep.** Заводится один wave: все `pending`-пункты выполняются вместе, помечаются `done`.
4. **Verify gate.** `cd spa-app && npx vitest run` — должен остаться green (на момент создания: **76/76**). Ноль изменений поведения UI (кроме пунктов, где изменение текста явно одобрено и помечено).
5. **Закрытие.** После batch — отметить выполненные, при новых находках открыть `STORY-SPA-HK02`.

### HK-001 — мёртвый словарь `languages.*` в `dictionaries.js`

**Что это.** В [src/i18n/dictionaries.js](../../../src/i18n/dictionaries.js) внутри `UI_DICTIONARY` для каждой из трёх локалей определена секция `languages`:

```js
// dictionaries.js:38-42 (et), :98-102 (ru), :158-162 (en)
languages: {
  et: 'ET Eesti',
  ru: 'RU Русский',
  en: 'EN English',
},
```

**Почему это мёртвый код (доказательство).**
- `grep -rn "languages\." src/` → **0 совпадений** — ключ `languages.*` нигде не читается через `t()`.
- Языковой селектор использует **хардкод** вместо словаря: `LANGUAGE_OPTIONS` с `nativeLabel` в [BoardPage.jsx:30-32](../../../src/pages/BoardPage.jsx#L30) (`'Eesti'`/`'Русский'`/`'English'`), и тот же массив **продублирован** в [IssuePage.jsx:9-11](../../../src/pages/IssuePage.jsx#L9). Рендер: `selectedLocaleOption.nativeLabel` ([BoardPage.jsx:125,138](../../../src/pages/BoardPage.jsx#L125), [IssuePage.jsx:179,192](../../../src/pages/IssuePage.jsx#L179)).

**Откуда взялось.** Остаток исходного gap **G6** (языковой селектор). Doc-закрытие G6 узаконило флаги в мокапах, но мёртвый словарь не убрали и не задействовали — зафиксировано как **RF4** в [re-audit-gap-closure-2026-06-15.md §4](../../analysis/re-audit-gap-closure-2026-06-15.md).

**Развилка (нужно решение оператора при batch-проходе).**
- **Вариант A (удалить, дефолт для HK):** вырезать 3 секции `languages` из `dictionaries.js`. Чистое удаление мёртвого кода, поведение не меняется. Риск — нулевой.
- **Вариант B (задействовать):** переключить селектор на `t('languages.<loc>')` вместо `nativeLabel`. ⚠️ Это **меняет видимый текст** селектора (`Eesti` → `ET Eesti` и т.д.) → косметическое UX-изменение, нужно явное одобрение; и тогда пункт ближе к G6/G8, а не к чистой уборке.

> Рекомендация для HK-накопителя: **Вариант A** (удаление), как соответствующий критериям включения (без изменения поведения). Если продукт хочет префиксы `ET/RU/EN` в селекторе — это отдельный UX-пункт, не housekeeping.

**Связь с другими стори.** [STORY-SPA-G8](STORY-SPA-G8-app-shell-refactor.md) (app-shell refactor) всё равно будет дедуплицировать `LANGUAGE_OPTIONS` (сейчас дубль в Board/Issue). Если HK-001 берётся **до** G8 — удалить только мёртвый словарь; дубликат массива оставить G8. Не делать работу G8 здесь.

**Как закрыть (Вариант A).**
- Удалить секции `languages` (3 шт.) из `dictionaries.js`.
- Подтвердить `grep -rn "languages" src/i18n/dictionaries.js` → 0.
- `npx vitest run` → green (76/76).
