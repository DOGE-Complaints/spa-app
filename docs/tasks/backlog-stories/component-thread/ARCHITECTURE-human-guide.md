## 1. Одной фразой

Мы делаем **отдельный блок «обсуждение»**, который можно пристегнуть к посту (сейчас) и к другим экранам потом — так же, как уже пристегиваются реакции. Кнопка Comment на полоске **не** знает про дерево комментариев: она говорит карточке «открой тред», а тред показывает свои состояния сам.

---

## 2. Три коробки — не мешать

1. **Карточка поста** — картинка, текст, полоска кнопок.  
2. **Пакет реакций** — лайк/пикер и «кто реагировал».  
3. **Пакет треда** (новый) — загрузка/пусто/свёрнуто/ошибка, дерево ответов, поле ввода, вложения, «подтверди личность».

Реакции на комментарии остаются из коробки 2, вставленной в узел дерева. Тред не учится открывать people.

---

## 3. Как у реакций (уже согласовали)

| Кнопка | Кто открывает поверхность |
|--------|---------------------------|
| Reactions | Карточка → пакет реакций → список людей |
| Comment | Карточка → пакет треда → discussion |

Одинаковая логика, разные владельцы UI.

---

## 4. Что на мокапах по слоям

- **M152** — «шапка» обсуждения под полоской: грузится / пусто / свёрнуто с превью / недоступно / узкий экран.  
- **M153** — внутри: ветки ответов, «ответить», черновик, вложение, ошибка отправки. Глубина ответа и **сколько файлов можно прикрепить** — настройки, не «зашили единицу в коде».  
- **M157** — если человек не верифицирован: табличка «сначала verify», уход на `/verify` (в lab — имитация), возврат с тем же черновиком, **сам пост не улетает**.

---

## 5. Почему конфиг, а не хардкод

В спеке отдельно: визуально влезает максимум **три** уровня отступа, а **разрешено ли ещё отвечать** — из `max_depth`. Это разные ручки.  
Вложения: лимит на композер/ноду (`maxAttachments`) задаётся константой/параметром — завтра на другой ноде может быть 0 или 3 без переписывания UI.

## 8. Residual chrome (человечески · §11)

1. **Пусто** — сначала pill «написать», не сразу большое поле.  
2. **Ответ** — поле появляется **под тем комментарием**, на который отвечают, а не внизу всего списка.  
3. **React / Reply** под пузырём — две компактные кнопки с иконками; реакции всё ещё из пакета реакций, тред их не «владеет».  
4. **Скрепка / самолётик** на композере — иконки уже есть в `public/icons/…/actions/`; не выдумывать новые SVG молча.  
5. **Линии треда** — непрерывный серый «позвоночник» + уголки; на ленте нужны фикстуры с вложенностью.  
6. **Узкий экран / ветки / «реакции жителей»** — включаем на lab, когда данные честно есть; не выдумывать счётчики.

## 9. Gaps M153a/b (человечески · §12)

1. **Post один раз** — после Reply/Post комментарий не должен появляться дважды (иначе дерево ломается).  
2. **Attach** — системный выбор файла, не «синтетический» чип; семьи файлов известны, точные MIME — TBD.  
3. **Токены** — пузырь / линии / кнопки ≥44px / Ready·Denied по M153b; без зелёно-красных бейджей.  
4. **Lab стенды** — loading/empty/unavailable, fail, attach-off, max-depth должны быть достижимы для аудита.  
5. **Реакции на комментариях (summary)** — HOLD, отдельной стори нет.
